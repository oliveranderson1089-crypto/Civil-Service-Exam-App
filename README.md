# 公考助手 Civil-Service-Exam-App

一个公务员考试备考工具：**网页 + 安卓 APK + 电脑桌面版（Linux .deb）**，多用户、可远程访问、可离线缓存（PWA）。
从「成语词语积累」起步，现已扩展成集**每日时政、常识/理论积累、申论 AI 逐点批改、遗忘曲线复习、题库、笔记与资料管理**于一体的备考工作台，并带微信推送。

> 在线体验（作者自部署）：**https://gk.gongkaopei2026.click**
> 安卓包：**https://gk.gongkaopei2026.click/apk**（免登录直下，当前 **v2.7**）
> 电脑桌面版：**https://gk.gongkaopei2026.click/deb**（Linux .deb，当前 **v3.6**）

### 真题批改（申论）

- **上传真题**（PDF / Word / 图片，扫描件自动 OCR）→ 自动拆出**给定资料**与各道小题，识别**题型、分值、字数要求**。
- **拆题时自动清洗杂质**：去掉页眉页脚 / 水印（「申公宝」「优路教育」「仅供学习」「第 N 页 共 M 页」等）和答题卡行号（100 / 200 / 300…）；给定资料把 PDF 版式的硬换行**拼回自然段**（每排排满再换行），材料序号（材料一 / 资料 2…）单独成行。老数据打开时也即时清洗，不用重传。
- 逐题作答，作答框**实时字数统计**（欠/超变色）；字数也是采分点之一。
- 作答支持**手写输入**（见「手写作答」），数位板 / 手指写字自动识别成规范汉字填进作答框。
- **作答时看得到给定资料**（以前真题模式只显示题干，材料根本看不到）：可停靠的「📋 给定资料」面板，
  电脑端进作答页**自动右半屏摆出**，左边答题右边看材料。面板上覆一层透明画布 ——
  **可用手写笔在原文上划重点**（荧光笔 4 色 / 笔 / 橡皮，防手掌误触），像考场那样。
  勾画**按卷子存 localStorage**，关掉重开还在。
- **参考范文可单独重生成**：范文是批改之外**独立的一次 AI 调用**，超时/失败就会空着 →
  结果页给「🔄 重新生成参考范文」按钮（`POST /api/shenlun/record/<id>/reference`），不用重跑整份批改。
- **AI 逐点批改**：对照给定资料提炼采分点，逐条给「已写到 / 部分写到 / 未写到」，附**对照材料原文**。大作文按 立意(10) / 结构(7) / 论证与材料运用(10) / 语言(8) 四维评分。
- **参考范文**单独生成并**严格校验字数**落在题目要求区间（塞进批改 JSON 里模型总会写短）。
- 结果页四页签：**维度评分 / 参考范文 / 原题·材料 / 作答原文**；做完一题弹窗提示**跳转下一题**。
- 各题型默认字数：归纳概括 150-250、综合分析 250-350、提出对策 300-400、贯彻执行 400-600、大作文 1000-1200（题目里写了就以题目为准）。

### 范文推荐

- 一个话题 = 一套仿真卷：**给定资料 4~6 则、总字数按真题规格**（不是随手几百字，也不会为压字数砍掉整则），配套 4~5 道题。
- 每道题都有**完整参考答案**；大作文另给「总论点 / 分论点 / 亮点」三行写作思路。
- ⚠️ **AI 仿真卷，非真题**：材料与案例均为 AI 命制，页面顶部有醒目标注，不可当真实事例引用。
- 分类浏览：大作文范文 / 应用文·小题，按话题筛选（基层治理、科技创新、乡村振兴、文化自信、生态文明、民生保障、法治政府、营商环境、数字治理、青年成长、共同富裕、城乡融合）。
- 「用这套卷练习」→ 复制成自己的真题卷，逐题作答 + AI 批改。

```bash
.venv/bin/python3 gen_essays.py --list        # 看哪些话题已生成
.venv/bin/python3 gen_essays.py 3             # 按热门顺序再补 3 套
.venv/bin/python3 gen_essays.py --topic 乡村振兴
.venv/bin/python3 gen_essays.py --daily       # 每日补一套（定时器就跑这个）
```
> 材料分则生成、逐则校验字数；总量以 9000 字为硬上限，但**绝不丢弃整则材料**（宁可长，不可残）。
> 参考答案生成后也会校验字数，超/欠自动重写——**模型对「多少字」很不敏感，只说一次根本管不住**。
> **每日更新**：`gongkao-essay.timer` 每天 05:40 跑 `--daily`，补一套还没生成的话题（大作文 + 应用文小题一次到位）；话题池 40+，排完可在 `gen_essays.py` 的 `TOPICS` 里加。新话题出炉会进**消息中心**并推到手机通知栏。

### 成文：把素材真正写成一篇大作文

**申论 → 议论文 → 成文**。素材背了不会用，等于没背——这里把散在各库的素材拼成一篇能交卷的大作文。

| 模式 | 怎么选材 | 什么时候用 |
|---|---|---|
| **📅 每日成文** | 按**素材更新的日期**：当天的人物事例 / 具体事例 / 理论论据 / 衔接表达**全用上** | 想知道「今天更新的这批素材，到底怎么用进文章」 |
| **🧩 综合应用** | **不限日期，AI 自己选题**——跨全部素材库挑真正用得上的。选题必须是省考真考的方向，不选空泛口号 | 每天一篇范文，练选题和调度素材 |
| **📋 应用文** | **14 个文种**分四类铺开，每种给「**🧭 提纲**（框架要点式）+ **📄 范文**（逐段带批注）」| 见下 |

**一个坑**：`theory_items`（政治理论）和 `changkao_items`（常考提法/成语）**根本不是按天更新的**——都是一次性铺进去的。所以「按日期取」压根取不到它们。改成：**骨架按当天素材的日期取，政治理论和常考提法按当天素材的话题去检索**（`_kw_of()` 抠关键词 → LIKE 匹配，一条都没命中就随机兜底）。这样每篇都用得上，也才是想要的效果。

**「用了哪些素材」是核对过的，不是 AI 自报的**。让 AI 报序号，服务端**逐条回正文里核对**（`_used_hit()`：衔接表达按模板骨架片段过半命中；成语/提法看词本身在不在；事例看里面的实词短语在不在），对不上的直接丢。实测一篇里 AI 报了 24 条，**3 条是虚报的，全被剔掉**。这个清单是给人回查素材用的，有水分就没意义。

一键补齐往期：22 天的素材 = 22 次 AI 调用，走后台任务（`bg_tasks`），单天失败不拖垮整批。

```bash
.venv/bin/python3 gen_write.py --compose        # 今天的综合应用范文
.venv/bin/python3 gen_write.py --daily          # 今天素材写一篇
.venv/bin/python3 gen_write.py --daily 2026-07-10
.venv/bin/python3 gen_write.py --backfill       # 补齐所有没写的日期
.venv/bin/python3 gen_write.py --list
```
> 生成逻辑只有一份（`app.py` 的 `_write_gen()`），`gen_write.py` 只是命令行入口——免得 App 里改了、定时器还在跑老的。
> **每日更新**：`gongkao-write.timer` 每天 08:40 跑（排在素材 08:00 更新之后）。

### 每日新闻视频（抓官媒 → AI 按公考价值筛）

**这个功能的价值不是「有视频看」，而是帮你把不值得看的滤掉。** 每条都附一句**为什么值得看**（考点在哪、能当什么素材），还有 2~3 个考点标签和一个「值得看」评分。

| 信源 | 内容 | 怎么拿的 |
|---|---|---|
| **央视网** | 《新闻联播》《焦点访谈》《东方时空》《今日关注》《环球视线》| `api.cntv.cn` **开放 JSON 接口** |
| **川观新闻**（四川日报社官方）| 四川本地 | 页面是 JS 渲染的，用无头浏览器渲染后抓 |
| **B 站官方认证号** | 央视新闻 / 人民日报 / 新华社 / 中国日报 / 央视网快看 / 四川观察 / **半月谈**（杂志社主号 + **半月谈公考**）| 见下（**不用登录、不用账号密码**）|

**信源只用白名单里的官方媒体**——不接受「随便什么博主」，因为**没法自动确认一个账号是不是真的**，那等于把把关的活儿丢回给你。B 站那几个号的 `mid` 是搜出来逐个核对过的（都带「官方账号」认证标）。

#### 四个板块：国内 / 国际 / 四川 / **备考**

「备考」是**讲解课，不是新闻**——半月谈公考发的是《申论热点年中盘点》（60 分钟）、《每天十分钟申论 80 分》、面试真题拆解这类内容。塞进国内/国际/四川都别扭（「这道面试题可以这样答」归哪个板块都不对），所以单开一个板块。

两处因此要**区别对待**（照搬新闻那套会出错）：

- **筛选标准反过来**：新闻看「信息增量、能不能当素材」，且超过 30 分钟要往后排；讲解课看「讲得实不实、能不能直接用在卷子上」，而且 **60 分钟的热点盘点恰恰是最值钱的那种，长不是缺点**。见 `PICK_RULES`。
- **时间窗要放宽**：新闻只要最近 2 天，但讲解课**没有时效性**——上周的申论盘点照样值钱。备考放宽到 **21 天**（`BOARD_DAYS`）。

> 顺带说个反直觉的发现：**半月谈杂志社主号最近几乎全是世界杯短视频**（7~12 秒，「450 美元一份世界杯草皮开售」这种），对公考没用——但不用特意处理，AI 归类会把它们判成「无」自然滤掉。真正对口的是「半月谈公考」那个号。

> 备考窗口有三周，就带出一个新问题：**同几条视频会天天被重新挑中**（入库时 `guid` 撞了才跳过），结果备考板块永远停在最早那几条、新课排不进来。所以抓取时**先把已入库的剔掉再送 AI**——既修了这个，也省了 AI 的钱。

> **数据源是一个个试出来的，不是拍脑袋定的**：
> - **央视网 `api.cntv.cn`**：真·开放 JSON 接口，而且每条都带 **`brief`（本期内容提要）** —— 这份逐条提要正是「值不值得看」的判断依据，**比标题有用得多**。栏目 id 是用无头浏览器从央视网的真实请求里抓出来的（不是猜的）。
> - **YouTube 官媒频道**：RSS 本身无需 key，但网络不稳，而且用 YouTube 拿央视内容对公考很绕。
> - **人民网/新华网视频频道**：JS 渲染 + 结构常变，正则抓不住。

#### B 站怎么抓的（**不需要登录，更不需要把密码写进代码**）

想拿某个 UP 的投稿列表，正规接口是 `x/space/wbi/arc/search` —— 但它**认登录**：哪怕用真浏览器打开人家主页、让页面**自己带着 WBI 签名**去请求，照样 `-352 风控校验失败`（这一条是实测抓包确认的，不是猜的）。

绕开的办法：**搜索接口不认登录**。所以改成「**搜 UP 主的名字 → 只留 `mid` 在白名单里的**」——搜索结果里会混进野生 UP（搜「四川观察」会混进个人号），按 `mid` 一过滤，剩下的就只有官方号的最新投稿，等价于拿到了投稿列表。风控要的 cookie（`buvid3` 等）由**真实 Chrome 打开 b 站首页时自动拿到**。

> **板块不能按「谁发的」定**：四川观察一样会发世界杯、发国际新闻。所以每条都让 AI 看标题+简介**逐条判**国内/国际/四川，判不出来或没考试价值的（娱乐、体育花边）直接丢掉。

**AI 筛选的实际效果**（某批）：68 条候选 → 选中 10 条。

- 《焦点访谈》「种在纸上的水稻」**★10**：「曝光基层粮食数据造假，直击耕地红线与基层治理痛点，**是申论典型案例和面试素材**」

- 而**娱乐类的自动被滤掉了**（成都偷吃大赛、龙泉山日出、非遗体验）—— 提示词里写死了「宁缺毋滥，别凑数」

看到有用的可以 **☆ 收藏**（当申论素材攒着）。展开「内容提要」能看到那一期逐条讲了什么，不用点开视频就知道该不该看。

#### 视频在 APP 内直接播放（不跳浏览器）

原来点播放是往外跳浏览器，**桌面版还跳不动**（WebKit 把 `_blank` 的新窗口请求直接吞了）。现在自己放。三种片源、三种放法，**播放地址在抓取时就算好存进库**，点播放是秒开的：

| 片源 | 播法 | 为什么 |
|---|---|---|
| **央视** | 优先**分段 mp4**（每段 5 分钟，一集切 4~6 段）| 是普通渐进式 mp4，`<video>` 原生就能放 —— 不依赖 MSE，桌面壳那个 WebKit 也吃得下 |
| **央视**（部分）| 拿不到 mp4 时退回 **HLS + hls.js** | 不是每条都有 mp4：《今日关注》四个画质档的地址**全是空串**（没转码），只剩 m3u8。而 WebKit 和 Chrome **都不原生认 m3u8**（实测 `<video src=m3u8>` 报 `code=4`），所以用 hls.js（靠 MSE，真壳里实测有） |
| **B 站** | 嵌**官方播放器** iframe | 人家的播放器页没有任何嵌入限制（无 `X-Frame-Options`、无 `frame-ancestors`），是官方给的分享方式 |
| **川观** | 抓取时渲染页面**截到直链** | 它的直链藏在 JS 里，静态页抠不到 —— 只能渲染页面、看它去请求了哪个视频文件 |

- 央视/川观的流实测**没有防盗链、而且 `CORS: *`**，所以能直接放进我们自己的页面，不用服务器中转。
- **分段 mp4 的坑**：一集切成好几段，得自己接成一条连续的时间轴 —— 进度条走的是**全片的秒数**，拖动时先算落在第几段、再跳到段内偏移，一段放完自动接下一段。
- **切段不再黑屏（双缓冲）**：单个 `<video>` 换 src 会黑闪一下。改成**主/副两个 `<video>`**：主视频在放第 i 段时，副视频后台 `preload=auto` 预载第 i+1 段（首帧早解好）；一段放完不重新加载，而是把副视频顶成主视频直接播 —— 无缝。跨段拖动仍走「装进主视频」的老路。HLS/川观单段不需要，就不建副视频。真桌面壳(WebKitGTK)里验证过切段无缝。
- **封面淡入**：B 站封面要一两秒才到，加载完再淡入，不硬闪。
- hls.js 放在**我们自己域下**（`static/vendor/`，404KB），**用到才加载**，没看视频的人不用扛。
- 播放器：空格播放/暂停、← → 各跳 10 秒、倍速、全屏、Esc 关闭。实在放不了的会**老实说明**并退回浏览器。
- 桌面壳同步升到 **4.3**：放开 `media-playback-requires-user-gesture` —— 我们的播放器是「点封面 → 取播放地址 → 再 `play()`」，中间隔了一次网络请求，用户手势早过期了，不放开就会被当成自动播放拦下。
- `backfill_play.py`：给「加播放功能之前」入库的老视频补上播放地址（跑一次就行）。

#### 全屏（手机端原来点了没反应）

手机端点全屏没反应，有两个不同的坑，都修了：
- **APK（Android WebView）**：网页点全屏（HTML5 全屏 API 或 `<video>` 原生全屏）都会走 WebView 的 `onShowCustomView` 回调，壳原来**没接这个回调**，所以点了完全没反应。现在接上了（把那个全屏视图盖到根视图、藏起 WebView），并让返回键先退出全屏。**要装 APK v2.8 才生效。**
- **手机浏览器**：iOS Safari 的 `div.requestFullscreen()` 根本不支持，只有 `<video>` 元素的原生全屏（`webkitEnterFullscreen`）能用。全屏按钮改成按平台分别走对的那条路。
- 横屏视频（央视/B站 16:9）进全屏时自动转成横屏；竖屏视频（川观 720×1280）保持竖屏不动。

### 每日复习量（自定义）

一天能背多少是因人而异的。原来写死 120 条（只能改环境变量），**堆起来就不想背了**。现在「今日复习」页顶部可以按组设：**词语句子 / 每日积累 / 错题**，各自一个每日上限，填 `0` = 不限（默认 40 / 20 / 10）。

- **超出上限的不会丢**，只是今天不出现 —— `next_due` 不动，明天照样在。
- 组内排序：**已经在复习轮里的排前面**（`stage` 高的先），别让复习中的一直往后堆、新词却天天冒出来。
- 常考成语的取词池子跟着上限走（上限 × 3，给自己收录的词留位置）；设 0 就把 894 条全放进来。
- **每日上限按「日历天」算，不是「每次请求」**：`review_today` 会扣掉**今天已经复习过的**数量（`last_done=today 且 next_due>today`）。不然会有个坑——常考池子（120+ 条）远大于每日量（40），做完 40 条一刷新，池子里剩下的又冒出 40 条，感觉像「进度被重置」。修了之后：做满 40 条，刷新/重开都显示「✅ 今日已完成 N 条」，不再冒新的。忘记的（`next_due=today`）不算完成，本来就该今天再出现。
- 接口：`GET/POST /api/review/limits`；`GET /api/review/today` 返回 `groups`（今天实际出的）、`pool`（到期的）、`done_today`（今天已完成的），能看出「今天出 40，其实积压了 119，已完成 68」。

### 小题训练：找点 + 写点

归纳概括 / 综合分析 / 提出对策，难点是**同一个**：**从材料里把要点找出来**。所以拆成两步，每步单独纠错——找点就错了，写了也是白写。

| 步骤 | 干什么 | 判什么 |
|---|---|---|
| **① 找点** | 在材料上**勾画**（只找不写）| **找漏**了哪个点（直接指出「就在这句」）· **找错**了哪几处（那是干扰信息）· **找重**了哪个点（材料里换了个说法而已，答案里只算一个）|
| **② 写点** | 照着勾到的地方**写要点** | 逐个采分点判「写到了 / 沾边但不到位 / 没写」，并指出**抄原文、没分条、加评价、漏关键限定词**这些毛病 |

判定完，红 / 黄 / 绿**直接标回原文**：绿=找对、红=找错（干扰信息）、黄=找漏（波浪线，点一下跳过去）。

**这套能成立的前提**：出题时就得存下「**采分点 ↔ 材料原文的逐字依据**」——

```json
points = [{"point": "概括后的要点", "evidence": "逐字来自材料的原句", "score": 3, "sents": [1,2]}]
```

没有 `evidence` 就只能凭感觉批，那等于没批。所以 AI 标的每个采分点都必须给依据，且**逐字出现在材料里**，服务端逐条核对，对不上的直接丢；一道题标不出 3 个点就判失败、重来。

**勾画粒度是「句」**，不是自由划词。申论找点本来就是找句子，句子边界明确才判得准——自由划词的区间对不齐采分点，判定必然变成玄学。点一句 = 选中/取消，**按住拖过多句 = 连选**（走 pointer 事件，鼠标和手写笔都能用）。

> 断句踩了两个坑：**引号里的句号会把句子劈开**（末尾剩个孤零零的「”」）→ 闭引号/闭括号要并回上一句；**「材料一」这种标题行也会成为可勾画的句子** → 标成 `head`，不让点。

**题目来源两条**：
1. **AI 按考试标准出题（字数对齐真题、材料与题型一一对应）**：
   - **字数照真题定**：查 2025 四川省考、2026 国考真题——一道小题对应的「给定资料N」通常由 **2~4 则子材料**组成、**总量约 1800~2500 字**（国考归纳概括的给定资料≈1800 字、综合分析≈2100 字、提出对策≈2000 字）。所以按「**3 则、每则约 550~750 字、合计约 1800~2400 字**」出。
   - **逐则生成 + 逐则校验字数**：模型对「多少字」很不敏感，一次说了压不住，所以出一则、实测字数、不够就带上这一稿要求扩写（`_find_fit_words`，和范文推荐 `gen_essays.fit_words` 同一套办法）。实测：归纳概括 693+721+697=2120 字 / 综合分析 816+744+809=2378 字 / 提出对策 699+561+665=1934 字，各则均达真题体量。
   - **材料随题型走**（`_FIND_MAT_SPEC`）：**归纳概括**→3 则「各地做法/成效/经验」；**综合分析**→3 则围绕一个「现象/观点」分层（是什么 / 为什么 / 怎么样）；**提出对策**→3 则「问题/成因/背景做法」（对策要从问题里长出来）；**贯彻执行**→3 则「背景/做法/成效-问题」，材料要能支撑所选文种的写作。只有大作文不属于找点训练，出题与上传都跳过。
   - **贯彻执行题**（用户新增）：选一个文种（讲话稿/宣传稿/公开信/新闻稿/倡议书/汇报/调研报告/简报/案例介绍/编者按/方案/建议书/通知/短评，来自 `GW_DOCTYPES`），**字数按该文种真题规格**（如短评 300~500、调研报告 500~800，对齐 2025 川考第三题=调研报告提纲、2026 国考第三题=短评）。题干设身份+文种+对象（`_find_gen_stem`），前端「贯彻执行」卡片下会冒出**文种选择条**（🎲 随机 + 14 文种）。找点这一步和归纳概括一样找内容要点，写点则按文种格式成文。
   - **贯彻执行题另判格式、且计入总分**（`_find_doctype` 从题干认出文种）：写点页顶部给出该文种的**格式骨架**提示；批改时除了内容采分点，AI 再逐项判**格式**（标题/称谓/正文结构/落款是否齐备）并打分。**总分 = 内容（约 75%）+ 格式（约 25%）**（如 20 分题 = 内容 15 + 格式 5，`fmt_full=max(2,round(full*0.25))`；采分点在 `_find_build` 里就按内容那 15 分分配）。结果里多一个 `format` 段（到位 ✅ / 欠缺 ❌ / 档次 / 格式分 / 点评），顶部总分旁标「内容 X/15 + 格式 Y/5」。实测：一份「有标题、缺落款、正文没分层」的简报判出 9/20（内容 8 + 格式 1），格式缺项全部点到。
   - **必须掺入干扰信息**（背景铺垫、无关细节、同义重复）—— 材料里如果句句是要点，那就没什么可练的。题干据材料另出（`_find_gen_stem`）。做题页顶部像范文推荐那样标出**给定资料总字数**（`material_words`）。

**做题记录**（`/api/find/records`、`/api/find/record/<id>`；视图 `findrec` / `findrecd`）：每次批改都留一条，「小题训练」里点「📋 做题记录」进去。列表显示题型/文种/总分（贯彻执行还带「内容 X/15 + 格式 Y/5」），点开可回看**当次的完整批改**（逐个采分点 + 格式板块 + 我写的答案），一键「再练这道」。批改结果的两块 HTML（`frScoreHtml` / `frResultBody`）做题页和记录详情共用。
2. **上传真题文档**：抽文本、拆材料和小题、判题型，**全部复用真题批改那条管线**（`_split_paper` / `_classify_questions` / `_pdf_text_or_ocr`，扫描件自动 OCR）；留归纳概括/综合分析/提出对策/贯彻执行，逐题标一套采分点（只有大作文不属于找点训练，跳过并告知）。

实测一道 AI 命制的归纳概括题（15 分 / 6 个采分点）：故意漏 3 个点、勾 2 句干扰句、同一个点勾 2 句 → **三类错误全部准确揪出**。其中一句干扰是「有老年人反映部分功能操作复杂」—— 题目问的是**成效**，这是问题不是成效，是个漂亮的坑。第二步交一份「抄原文 + 没分条 + 加评价 + 漏点」的答案 → 判 5/15，四个毛病全被点名。

- 接口：`POST /api/find/gen`、`POST /api/find/upload`、`GET /api/find/paper/<id>`（**采分点绝不下发**，否则前端一翻就看见答案）、`POST /api/find/check`、`POST /api/find/grade`。

### 应用文成文（提纲 + 范文，14 个文种铺开）

**应用文和大作文根本不是一回事**：大作文考「怎么论证」，应用文考「**格式 + 要点 + 语言得体**」。所以不能照搬「丢一堆素材让它写」——必须先定：**什么文种 · 就什么事 · 我是谁 · 写给谁**。

**文种按「考什么」分四类**（每种都自带一个示范情景，第一次铺开时直接用）：

| 类别 | 文种 |
|---|---|
| **宣传演讲类**（面向人，讲感染力和现场感）| 讲话稿 · 宣传稿 · 公开信 · 新闻稿 · 倡议书 |
| **总结说明类**（面向上级/同行，讲条理和成效）| 汇报 · 调研报告 · 简报 · 案例介绍 · 编者按 |
| **方案建议类**（面向执行，讲可落地）| 方案 · 建议书 · 通知 |
| **观点主张类**（面向读者，讲观点鲜明）| 短评 |

**每个文种给两样**：

| | 是什么 | 看它干嘛 |
|---|---|---|
| **🧭 提纲** | **框架式、要点式**：骨架摆出来，每块下面用短句列要点（这一块放什么、写到什么程度、用哪种表述）| 一眼看清「这个文种由哪几块组成」 |
| **📄 范文** | 成篇的文章，**逐段带批注**（每段是哪个部件、为什么这么写、阅卷看什么）| 看成品长什么样 |

> **提纲本身不是文种**，是一种**呈现方式**（框架式、要点式），任何文种都能套。所以它和范文共用同一套「文种 + 场景 + 身份」，只是产出从「成篇文章」换成「骨架 + 要点」。**先看提纲再看范文，才知道一篇文章是怎么长出来的。**

**两个导航栏**（和议论文成文一样分两栏，各管一件事）：
- **📋 文种大全**：「⚡ 一键铺开所有文种」+ 按类别浏览各文种的提纲/范文。
- **✍️ 自选成文**：选文种 + 填「就什么事 · 我是谁 · 写给谁」→ 写这一篇。

**怎么用**：
1. 先进「📋 文种大全」点「**⚡ 一键铺开所有文种**」→ 后台给每个文种各写一份提纲 + 一篇范文（先提纲后范文），先把格式和结构看明白。
2. 之后进「✍️ 自选成文」**针对同一文种换话题积累**：选文种 + 填新的「就什么事发文」→ 再写一篇。文种大全里按「类别 → 文种」摆，每个文种下挂着积累的话题。

实测新闻稿提纲（5.5 秒 / 252 字）——要点式、数字用 `XX` 占位（不编数据），每块附「阅卷看什么、丢分在哪」：
```
标题：我区数字政务服务大厅正式启用
导语：今日，我区数字政务服务大厅正式启用，标志着…
主体：
· 一是大厅概况：建筑面积XX平方米，设置XX个综合窗口…
· 二是创新举措：推行"一窗受理、集成服务"…
· 三是数据成效：办结XX件，平均办理时间压缩XX%…
```

- 公文规范表述（`gongwen_items`）本来就是**按结构部件归类**的（开头·缘由 / 主体·举措 / 结尾·号召…），正好当零件用，让 AI 对号入座。
- 「用了哪些规范表述」**直接回正文里扫**，不问 AI（它虚报也漏报）。
- 批注/说明的 `text` 必须**逐字来自正文**，服务端核对，对不上的丢掉。
- 接口：`GET /api/write/gwspec`、`GET /api/write/yylist`（按类别→文种分组）、`POST /api/write/yingyong {doctype, scene, role, audience, form}`、`POST /api/write/yingyong/batch`（后台铺开）。

**题从哪来 —— 按题型分，不是按板块分**（判断推理是**混合**的）：

| 引擎 | 用在哪 | 为什么 |
|---|---|---|
| **程序化生成**（`figgen.py`）| 资料分析全部 · 数量关系全部 · **判断推理的图形题** | 可构造，**答案由构造保证**。AI 出这类题会算错 |
| **AI 出题 + 题库缓存**（`drill_bank`）| 常识 · 政治理论 · 言语理解全部 · **判断推理的定义/类比/逻辑判断** | 考的是**知识和推理**，构造不出来。出好的题攒进题库，某题型**首次约 11~25 秒，之后秒取** |

> **老实说明一处做不到的**：讲义里图形推理还有「立体图形（折纸盒/三视图）」，二维 SVG 构造不出可靠的立体题，硬做出来答案站不住脚 —— **所以不出**，专项练页面直接写明，不假装有。

> AI 出的每个题型都单独写了**出题要点**（`_AI_SPEC`）—— 不写清楚，AI 会把「判断意图」出成「概括主旨」。实测：定义判断给完整定义 + 四个例子（互殴、事后追打、被辱骂 —— 三种典型不成立情形）；削弱论证的正确答案是**年龄这个混杂变量**（切断因果），干扰项也是混杂变量但削弱力度弱。

**三档难度，真正改变题目**（不是贴个标签）：

| | 数量关系 | 判断推理（图形）| 资料分析 | 知识类（常识/理论/言语）|
|---|---|---|---|---|
| **入门** | 只出「一个公式套完」的（工程/行程/利润/周期），数字整 | 只出直观规律（数元素、数边）| 一步（比重、倍数），数字整 | 单点正面直问，四选项差异明显 |
| **进阶** | 常规两步 | 五类规律都可能 | 两步（增长量、增长率）| 需要辨析，有一个较像的干扰项 |
| **考场真实** | 上浓度/容斥/排列组合，**数字变脏**（甲 11 天、乙 16 天 → 6.5 天）| 偏隐蔽规律（线条数、封闭区域）+ **镜像干扰项** | 多步（年均增长量、比重变化）+ 增速不圆整 | 干扰项**贴着常见错法**（易混概念、偷换时间/主体/范围）|

| 数量关系 | 0.65 | 0.50 | **0.40** ← 做对 4 成不是你菜，是这题本来就难 |
| 常识判断 | 0.80 | 0.65 | 0.55 |
| 言语理解 | 0.87 | 0.72 | 0.62 |

| 判断推理 | 0.85 | 0.70 | 0.60 |
| 政治理论 | 0.85 | 0.70 | 0.60 |

**题量 / 模式 / 记录**（参考每日测试的做法）：

- **题量**：5 / 10 / 15 / 20 题
- **背题模式**：选完立刻判 + 给解析和秒杀技巧 —— 边做边学
- **测试模式**：**答案不下发到前端**（题暂存服务端，只发题干选项），做完交卷、服务端判分，可以翻回上一题改 —— 更像考试
- **每题计时**（资料 60 / 判断 45 / 数量 70 / 常识·理论 30 / 言语 50 秒）。超时不打断只提醒 —— 考场上超时也得做完
- **做题记录**：每次做完留一条完整记录（题目 + 我的作答 + 用时），**可以回看每一题**，不是做完就丢。表 `drill_records`
- 错题**自动进错题本**（和巩固测试同一套）

> **程序化出题：2400 道抽检 + 600 道独立验算，0 异常。** 期间揪出两个真 bug：
> - **干扰项撞上答案** → 那题就有两个正确选项。`_mq()` 现在强制四选项互不相同（撞了就挪开）。
> - **格式不一致等于送分**：`29.0% / 23.0% / 35.0% / 26%` —— 一眼看出哪个不一样。现在四选项统一格式；解析里的答案也用 `{ans}` 占位符统一填充，否则选项写「6.0天」、解析写「6 天」，同一个数两种写法。

> **AI 出题也踩了一个**：逻辑填空的干扰项是废的 —— 「施行 / 掩饰 / 减轻 / 接二连三」，一眼就能选。根因是**从词库随机抽词**喂给 AI，那些词彼此不相关，它就拿来凑数了。
> 改成：**正确答案从我们库里挑**（保证考的是积累过的词），**三个近义混淆项让 AI 自己造**，四个词要「放在一起才需要辨析」。现在出的是「美轮美奂 / 富丽堂皇 / 金碧辉煌 / 宏伟壮观」，解析逐个讲区别。

### AI 题必须过双模型核验才发给你做

**为什么非做不可**：135 道抽检下来，单模型出题的答案一致率只有 **89%** —— 每 9 道就有 1 道存疑。而且真抓到硬伤：「生态文明八个坚持」那道说「山水林田湖草**沙**」多了个「沙」，**那是错的**（"沙"是正式表述）。**背下错答案，比不做还糟。**

- **出题**：DeepSeek　**核验**：智谱 `glm-4-plus`（另一家模型）
- **绝不把原答案给核验模型看** —— 给了就会被锚定，核验就白做了
- 核验模型独立作答 + 独立判断题目本身有没有毛病（事实错 / 答案不唯一 / 无正确答案 / 有歧义）
- **答案不一致或有缺陷 → 入库但标为存疑，不发给你做**（存疑的题留着可回查，但绝不能拿去背）

**实测效果**：230 道存量题跑完核验，**筛掉 33 道（14%），其中 12 道有事实错误**。现在你做到的题都是双模型一致的。题型卡上直接显示「✓ 8 道已核验（筛掉 3）」。

> 按题型看可靠性差距很大：**判断推理的逻辑题（削弱/定义）100% 通过** —— 这类题对错可推演，AI 出得住；**科技常识只有 50%**（8 道砍了 4 道）—— 这个题型 AI 出得最不靠谱。数据说话。

### 成语：真实例句 + 易混辨析

**例句优先用真语料，不是 AI 编的。** 库里有人民网、共产党员网爬来的时政原文和时政要文 —— 先去里面找含这个成语的**真句子**，找到就标真出处：

```
【潜移默化】文明新风潜移默化地融入日常生活，成为乡亲们的价值取向和行为准则。
           —— 人民网时政《文明之花绽放乡村沃土》
```

990 个成语/实词里，**196 个（20%）在真语料里找到了真例句**。找不到的才让 AI 仿写，并**老实标注「✎ AI 仿写（人民日报文风）」** —— 不糊弄。复习卡翻到背面时懒加载（你真背到哪个才给哪个生成，不预先烧钱）。

**易混辨析**（逻辑填空考的就是「这几个近义词该用哪个」）：给 2~3 个最容易混的词，逐条说清**词义侧重 / 感情色彩 / 搭配对象 / 用错示例**，再给一句**口诀**和一道**填空自测**。对比词**优先从我们自己的成语库里挑**，辨析完这几个词都在你的复习范围内，点一下就能跳过去看它的典故。

```
【一蹴而就】🔑 一蹴而就强调过程短，一劳永逸强调结果久，轻而易举强调难度低。
```

### 常考 ↔ 成语词语积累：**双向同步**

两边是**同一份收藏**，只删一边等于没删（下次打开常考还是实心星，再点一下又加回来）。现在：

- 常考里 ★ → 同步进「成语词语积累」的对应分类（成语→成语，实词→词语）
- 常考里取消 ★ → **同步从「成语词语积累」删掉**
- 从「成语词语积累」删词 → **同步取消常考那边的 ★**
- `POST /api/entries/sync` 对账：历史数据两边各存各的，一键补齐（实测补了 7 个）

### 小记：随手记（悬浮球）+ 电脑端去掉板块栏

**随手记**：悬浮球里加了 📒。小记本来只有「进那个模块」一条路，但真要记的时候人都在看别的东西（做题、看时政、读范文）——**跳走一趟回来，思路就断了**。所以做成**浮在当前页面上**的一小块：写完点「记下」，页面纹丝不动。原来的小记模块**照样保留**（要整理、翻历史还是得进去）。

浮层**可拖可缩放**（标题栏拖动移位、右下角拖动改大小，位置和尺寸都记住）。图片支持**拖进来**和 **Ctrl+V 粘贴**。

**收各种文件，不只图片**：随手记原来只有「🖼 图片」一个入口，拖非图片进去会被「只能放图片」挡掉。现在加了「📎 附件」按钮，**拖任何格式的文件（PDF/Word/表格/压缩包…）也能上传** —— 图片进图片区、别的进附件区，走的是和小记编辑器同一个 `attachments` 字段。小记编辑器的「附件」按钮本就不限格式（`#cp-attfile` 没有 `accept`），手机端只显示图片是**旧版 APK 的文件选择器问题**，装 v2.8 即好。

**看图统一**：草稿里的图和已发布的图原来走两条路 —— 前者是浮层，后者跳全屏阅读器，所以「上传前预览正常、上传后点开巨大」。现在都走同一个浮层（92vw/78vh 上限）。**手机端双指捏合缩放**（实测外扩到 3.89×、内捏到 0.78×），电脑端滚轮缩放 + 拖动平移。

**复制图片是真复制图片**：原来复制出来只是一串 URL（粘贴到别处就是个地址）。现在用 `ClipboardItem` 把**图片本身**写进剪贴板，jpg 自动转 png（剪贴板只认 png）。电脑端和手机端都验证过。

**电脑端去掉左侧板块栏**：板块只是个归类，不值得占掉最左边一整条。改成 **写的时候在编辑器里选（下拉）+ 看的时候在顶部下拉筛** —— 功能一样，屏幕省下来给正文。

### 手写作答

申论作答框旁边的「✍️ 手写输入」，是给**数位板 / 手写板**（接电脑）和手机手指准备的：在田字格里写字 → 停笔自动识别 → 填进作答框，像手机自带手写输入法一样。

- 前端 `<canvas>` 捕捉笔迹（`pointer` 事件，兼容笔 / 鼠标 / 触摸），把每一笔的坐标 + 时间戳发给后端。
- **自动上屏 + 流水线（默认开）**：停笔即把这个字**入队、立刻清空画布**接着写下一个，识别在后台**排队按序填字**——连续写申论不用等每个字识别完（`hwFlush`/`hwPump`）。写错点候选栏里别的字可替换刚上屏的字；关掉"自动上屏"则回到"写完点候选"的手动模式。
- **识别默认走云端 Google（最准）**，另有「更快」可选（`hwCall`）：
  - **默认·云端 Google**：`/api/handwrite` 调 **Google 手写识别**（本机直连不通，**经本地代理出网**；端口会变，多端口兜底，可用 `GONGKAO_HW_PROXY` 或 `config.json` 的 `hw_proxy` 指定）。约 0.6s，给候选列表，最准。手机、电脑都默认用它。
  - 手写栏勾「**更快**」→ 用**端上/本地引擎**（准度稍逊，没结果自动退云端）：
    - 手机：**ML Kit Digital Ink**（`zh-Hani`，端上离线、瞬时；`Handwrite.java` + `window.__hwNative` 回调；`hwPrepare` 预下载模型）。
    - 电脑/网页：**Zinnia**（`/api/handwrite/local`，ctypes 直调 `libzinnia` + tegaki 简体模型，离线约 10ms；`_zinnia_norm` 按外接框居中归一化，位置/大小无关）。依赖 `apt install libzinnia0 zinnia-utils tegaki-zinnia-simplified-chinese`，模型路径可用 `GONGKAO_ZINNIA_MODEL` 指定。
  - 实测：Zinnia ~10ms / Google ~0.6s / 智谱 GLM-4.6V 视觉 2–3s（更慢且无候选，故不用于逐字输入）。准度 Google ≈ ML Kit ＞ Zinnia。
- 支持撤笔 / 清空 / 空格 / 换行 / 删字；填字后自动触发字数统计。

### ✏️ 通用手写批注（Ink）—— 随处勾画，笔迹保留

一块透明画布盖在**任意内容**上，随处拿笔勾画做笔记。入口：工具球「✏️ 批注」（任意页面）+ PDF/Office 预览条上的「✏️ 批注」。一套系统解决三件事：

- **笔尖对齐**：坐标是「指针相对画布」直接算的，**笔尖落哪画哪**（pdf.js 自带那支笔笔尖是歪的、还没法存 —— 已把它的编辑按钮注 CSS 藏掉，只留这个）。
- **橡皮 + 全屏清除**：橡皮划过即擦（`destination-out`）；「🗑 清屏」一键抹掉整页笔迹，且**可撤销**（`↶` 找回）。笔/荧光笔/橡皮 + 5 色 + 粗细。
- **笔迹保留**：按「页面 / 文档」存本地，**关了再打开还在**（PDF 按文件路径存 `ink:mat:<file>`，其它视图按 `ink:view:<名>`）。
- **PDF 跟随滚动**：pdf.js 是同源 iframe，读它内部 `#viewerContainer` 的滚动 → 笔迹跟着页面一起滚、贴在原位（y 存成内容绝对像素）。
- **一般视图用视口坐标**（`scroller=null`）：画在哪个屏幕位置，关了再开还在那个位置，不受页面滚动影响。> 曾试过让一般视图也「跟随整页滚动」（存内容绝对坐标），但一旦关闭后页面滚回顶部，坐标很大的笔迹就被画到可视画布**下方（屏外）**、看着像丢了 —— 一般视图内容通常一两屏，视口坐标最稳。需要跟随滚动的是 PDF，走 iframe 内部滚动那条路，不受影响。
- 笔引擎和草稿本同源：**压感**（数位板变粗细）、**合并采样**（`getCoalescedEvents`）让线顺滑、用过笔就忽略手指防手掌误触。

> 已验证：指针落 (400,300) → 笔迹正好在 (400,300)（对齐准）；橡皮擦除、清屏+撤销、关闭重开笔迹恢复都正常。
> v1 限制：PDF 改变缩放后旧笔迹可能错位（按当时内容像素存）；一般视图不跟随页面滚动（视口坐标，在当前屏批注，换来「关了再开一定还在原位」的稳定）。

### 🖍 划重点（**按模块**，各有各的考法）

不用通读全文：进到有内容的模块，正文顶部会长出一张「🖍 重点 · 考点」卡片，点一下 AI 就在原文里标出该记的地方。

**关键是：每个模块划的东西根本不是一回事。** 一套「提法/数据/政策/金句」套到常识、错题、范文上就是驴唇不对马嘴：

| 模块 | 考点类型 | 这个模块该看什么 |
|---|---|---|
| 每日时政 | 提法 / 数据 / 政策 / 金句 | 考的是「谁在什么时候提出了什么」|
| **常识积累** | 定义 / 数字 / 易混 / 常考 | 常识是**细节题**，选项往往只改一个字（「最早」改成「唯一」）→ 要划的是**能被改动的那个词**，不是整段结论 |
| **理论基础** | 论断 / 时间 / **首提** / 关系 | 考的是**归属和位置**：哪句话是谁说的、哪个是核心哪个是基础。「××是××的核心」必划 |
| **错题** | **陷阱** / 正解 / 知识点 | 复盘只有一个目的：下次别再错 → 先划陷阱，再划正解 |
| **范文 / 成文** | 分论点 / 论证 / 素材 / 表达 | 看范文不是看内容，是**看它怎么写的** → 划可以搬走复用的「结构件」|
| 经典著作 | 观点 / 背景 / 金句 / 常考 | 既考常识，也是申论的引用来源 |
| 时政要文库 | 提法 / 目标 / 举措 / 金句 | 中央文件原文，考点集中在新提法和量化目标 |
| 创新理论词典 | 定义 / 提法 / 出处 | 术语题就考「完整表述」和「出处」|
| 古诗文 | 名句 / 典故 / 考点 | 常识考作者朝代，申论要引名句 |
| 常考（成语实词）| 释义 / 易错 / 辨析 | 就考**用得对不对** |
| 批改结果 | 扣分 / 亮点 / 改法 | 要划的是**可执行的动作**，不是分数 |
| 题型讲义 / 基础知识点 / 题目解析 | 方法 / 格式 / 易错 / 公式 / 陷阱 | 划**照着能做题的东西** |

实测同一个引擎在不同模块划出来的东西：常识划出「**折射角小于入射角**」「子时（23:00-1:00）」；理论划出「**2022 年二十大首次系统阐述**中国式现代化」；错题划出「人的价值最主要体现是个人对社会的贡献」；范文划出分论点句和衔接表达。

- 类型清单和「该看什么」**只有一份**，在服务端 `MK_PROFILES`（`GET /api/marks/profile?scope=`），前端不另写一遍。
- **实现方式仍是通用的**：不重渲染页面，而是**在已经渲染好的 DOM 里**找到那些句子、就地包一层 `<mark>`（`TreeWalker` 收文本节点 → 拼成整串 → 定位 → `Range.surroundContents`；长句先标、从后往前改，避免偏移失效）。**换句话说：引擎通用，划法按模块** —— 加一个模块只要往 `MK_PROFILES` 里加一条。
- 顶部结果条：`🖍 划出 8 处重点 · 看清单 · ✕`；点清单里任一条 → **跳到原文那句并高亮闪动**。
- **缓存 key 带 scope**（`md5(scope + text)`）：同一段文字在不同模块划法不一样，只按文字哈希会串味。
- 硬要求：AI 挑的句子**必须逐字来自原文**，服务端逐条核对，对不上的直接丢弃 —— 否则在 DOM 里根本找不到、标不上去。
- 接口：`POST /api/marks {text, scope}`（`force:true` 重划）。

> 记住的位置会在**启动时和窗口变化时按当前窗口夹回可视区**（`fabClamp`）。否则在更小的窗口里（比如桌面版）球会停在窗口外面，表现就是「悬浮球不见了」——这正是桌面版踩过的坑。

### 通用停靠面板（`createDock`，草稿纸和 AI 共用一套）

草稿纸、AI 面板、**申论的「给定资料」面板**都不是一点就整屏盖住，而是半屏停靠、随手可调（三处共用同一份实现）：

- **半屏是默认值**：AI 默认右半屏（手机下半屏），草稿纸默认下半屏，给定资料默认右半屏。
- **✥ 手柄**按住拖到屏幕任一边 → 松手吸附成**那半边**（下/上/左/右；拖到正中 = 全屏），拖动时有预览框；**⛶** 一键全屏 / 还原。
- **交界处的分隔线可直接拖**改大小（悬停变色 + resize 光标，命中区 18px），**双击复位**成一半。
- **每个停靠位分别记住比例**（`localStorage` 的 `padDock` / `aiDock`），换停靠位不重置，刷新/重开直接沿用。
- **内容自动让位**（`applyPush`）：面板占了半屏，页面**不是被盖住**，而是把内容挤到剩下的可见区（给 `body` 加 `--push-l/r/t/b` 内边距，顶栏和视图都在普通流里，所以整页让位、**卡片网格自动重排**）。左/右停靠时内容重排成更窄的列；下/上停靠时加相应内边距，保证能滚到最后一条。
- **悬浮球自动让路**：被面板压住就挪出去，面板全屏时隐藏。
- 面板可以停不同边（比如 AI 左半屏 + 草稿纸右半屏），互不打架。

### 草稿纸（随时可调用，**不做识别**）

**任何页面**都能从悬浮球叫出来（不再只限做题页）——一块可书写的画布，纯手写演算（竖式、画图、涂改），也可以对着「成语词语积累」在旁边**练着写字**。**不会把字迹转成标准汉字**，也不发给服务器。

- **停靠位可拖**：工具栏的 **✥** 按住拖到屏幕任一边 → 松手就吸附成**那半边**（下 / 上 / 右 / 左半屏；拖到正中 = 全屏）；拖动时有半透明预览框。
- **半屏只是默认值**：交界处那条**分隔线可以直接拖**（像编辑器分栏，悬停变色 + resize 光标，命中区 18px），想占多少占多少；**双击复位**成一半。
- **每个停靠位分别记住你拖成的比例**（`padSizes{bottom,top,left,right}` 存 `localStorage`）：右半屏拖成 380px、下半屏拖成 240px，来回切换各是各的，刷新/重开也一样。换停靠位**不会**把你的比例重置。
- 纸被拖窄时工具栏自动换紧凑排版（`.pad.narrow`），不会挤成三行吃掉书写区。
- **悬浮球自动让路**：停靠后若球压在纸上，自动挪到纸外；全屏书写时直接隐藏（用纸上的 ✕ 关）。
- 笔画按**画布宽度归一化**存，所以从「下半屏」拖到「右半屏」，字迹等比缩放不变形。

- **笔 / 荧光笔 / 橡皮**：5 种颜色 + 粗细滑杆。橡皮用 `destination-out` 只擦笔迹、不擦纸上的格子。
- **数位板压感**：`pointer` 事件取 `pressure`，有压感时逐段变粗细；`getCoalescedEvents()` 取高频采样让线更顺（**该接口在部分 WebKit 上返回空表，代码会退回事件本身**，否则一笔只剩一个点）。
- **防手掌误触**：一旦用过笔（`pointerType==='pen'`），之后的触摸点不再落笔。
- **撤销 / 重做**（Ctrl+Z / Ctrl+Y）、**多页**（最多 20 页，可加页 / 删页 / 清空本页）、**纸张**空白/方格/横线切换。
- **存为图片**：导出当前页 PNG（白底黑字，方便贴错题本）。
- **自动保存到本地**：笔画向量存 `localStorage`，切页面、刷新、关掉再打开草稿都还在；**换页面不会收起**（正好一边看词一边练写）。

### 草稿本（错题本里，平时打草稿用）

错题本页顶部的 **📓 草稿本**：可以建**多本**、长期留着的草稿，**存在服务器**，手机和电脑同步。同样只手写不识别。

- 列表按更新时间排，每本显示**封面缩略图**（第一页，白底黑字，客户端生成的 JPEG）、页数、更新时间，可**改名 / 删除**。
- 打开就是整页的草稿纸，用的是同一套画布引擎（笔/荧光笔/橡皮、压感、撤销重做、多页、方格纸、导出 PNG）。
- **自动保存**：停笔 1.2s 存一次，标题旁显示「未保存… / 保存中… / 已保存」；`Ctrl+S` 立刻存；关闭时再存一次。
- 和做题时的「随手草稿纸」**互不干扰**：进草稿本前先把随手草稿存进 `localStorage`，退出时原样还原（`padMode` 切换）。
- 表 `drafts(user_id, title, data_json, pages, thumb, updated_at)`；接口 `GET/POST /api/drafts`、`GET/POST/DELETE /api/drafts/<id>`（整本覆盖写，`title` 单传即重命名）。

### 题目解析（讲义识题）

讲义里常常「有知识点、有例题，但例题没答案」。把它丢进来：

1. 上传 PDF / Word / PPT（扫描件自动 OCR，扫描页 OCR 已提到 300dpi）。
2. 本地先用正则筛出「像有题目」的页（`（　）`、`A．`、「下列…正确的是」，**以及图形推理 / 类比推理这类无文字选项的题干**：「从所给…四个选项」「呈现一定的规律性」「分为两类」、带年份省份的真题标注等），只把这些页送去问 AI，省一大笔调用。
3. **配了视觉模型（见「视觉模型」）就把候选页渲染成图，让模型「看图做题」——图形推理 / 类比 / 图表题直接对着图形选答案、讲规律**；没配则退回纯文字（能对上历年真题的给公认答案，否则标「见原图」+ 解题思路）。
4. AI 逐题给出**答案 + 解析**（含其他选项为什么不选），并标注题目所属模块。
5. 生成副本 PDF：**原页排版一页不动**，解析页插在该页之后（`qpdf` 交错拼接）。
6. **原件与副本都留在资料库**，详情页可一键对比打开。

后台任务带进度条，前端轮询；默认最多处理前 80 页（`GONGKAO_DOCQA_MAX_PAGES` 可调）。

**可一次上传多份讲义**（文件选择器支持多选）：每份建一个任务，后端用信号量**排队处理、一次只解一份**（`_docqa_gate`），避免多份同时跑把视觉接口挤爆（429）；排队中的任务显示「排队中…」。

### 视觉模型（图片识别 · 智谱 GLM-4.6V）

DeepSeek 只有文字能力，所以**图片相关**统一走智谱 GLM-4.6V（OpenAI 兼容），**文字任务仍走 DeepSeek**，互不影响、也更省钱。

- 配置写在 gitignored 的 `config.json`：`vision_base`（`https://open.bigmodel.cn/api/paas/v4`）、`vision_key`、`vision_model`（`glm-4.6v`，旗舰，接图形推理）、`vision_model_free`（`glm-4.6v-flash`，**完全免费**，接拍照 / 读图）。
- `vision_chat()` 统一封装：`prefer="free"` 先用免费 flash（读图够用），**429 / 失败自动重试并退到旗舰**；`prefer="pro"` 直接上 `glm-4.6v`（图形推理这类硬任务）。
- 已接入：**拍照 / 粘贴识别**（`/api/ocr`，比 tesseract 更能读手写和排版，失败退 tesseract）、**AI 图片附件**（`/api/ai/extract`）、**题目解析的图形推理页**（渲染成图交给 `glm-4.6v` 看图作答）。
- 期望值：读题 / 读手写 / 理解图片会**大幅改善**；纯抽象图形推理明显好转但非题题全对（公认难点），不够准可把那一路升到 `glm-5v` 或带 thinking 的模型。

### 备考规划（AI 排计划）

任务清单的第一个页签。先填一次**备考信息**（考试、考试日期、每天可学分钟数、薄弱环节、备注），之后每天点「让 AI 排今天的计划」。

关键在于 **AI 看得到真实学情**，不是空泛地劝人努力。排计划前后端会先算一份「学情快照」丢给模型：

- 今天到期的复习条数（词语句子 / 每日积累 / 错题，分开计数）
- 错题按板块分布（哪个板块错得多）
- 未做的模拟卷、今日新增的常识 / 时政 / 素材 / 概括句条数
- 每日任务完成情况、已批改的申论题数
- 距考试还剩多少天（只用来判备考阶段：冲刺 ≤14 天 / 强化 ≤45 天 / 基础打底；界面上不做倒计时）、今天有多少分钟、哪些是薄弱环节

模型只能引用快照里的数字，且**总时长必须贴近可用时间**。产出形如：

```
💡 优先复习到期内容与错题，再补数量关系与资料分析短板，最后积累新增常识与素材。
1. [复习]   复习到期词语句子 13 条 + 每日积累 118 条（共 131 条）   30 分钟  → 今日复习
2. [错题]   复习错题 4 道（常识判断 3 道 + 政治理论 1 道）          15 分钟  → 错题本
3. [资料分析] 做 15 道资料分析真题并订正                            40 分钟  → 题库
...
```

每条都有**模块色标 + 预计分钟 + 「去做 ›」直达对应页面**，勾选后显示 `今日进度 3 / 6 · 85 / 150 分钟`。

- 手动加的待办和 AI 排的计划**并存**：重排只覆盖 `source='ai'` 的条目，手写的不会被冲掉。
- 当日重点（`summary`）落库到 `plan_profile`，按日期生效，**刷新/隔天重进都不会丢**。
- 今日计划会进**消息中心**（还剩几项没做 / 今天还没排计划），也会在 08:20 随微信推送发出来。
- **同步进互监待办**：今天的计划会镜像到「互监待办」（带「📅 规划」标记），搭档可**交叉打勾监督**你完成（`_sync_plan_to_shared`，计划重排/增删自动同步）。
- **任务条数跟着可学时长走**：`n_task = clamp(minutes/45, 4, 12)`——每天 6~8 小时就该排 8~11 条，不再固定 4~6 条。

### 图形推理 / 资料分析：程序化出题（`figgen.py`，巩固测试与模拟卷共用）

**为什么不交给 AI**：图形推理——它画得出 SVG，但「图形规律」和它自己给的答案经常对不上；资料分析——它会写「根据材料…」却**根本不给材料**（实测过）。所以这两块收回代码：

- `_gen_figure_q()`：按规律构造 SVG——**旋转 / 元素数量 / 边数递增 / 线条数 / 封闭区域数** 五类；答案是构造出来的必然正确，干扰项按「差一个属性」造（旋转题放一个**镜像**——镜像靠旋转得不到）。
- `_gen_ziliao(n)`：先造一份**内部自洽**的统计数据（等差设计，比重/增长率都是整数），再由代码算答案，出 **比重 / 增长率 / 增长量 / 年均增长量 / 倍数 / 比重变化** 六类；干扰项踩真实陷阱（分母用错年份、年均增长除以 4 而非 3、**混淆「百分点」与「%」**）。
- 材料存成 JSON（`{"type":"table"|"bar"|"line"|"pie",…}`；图形题存 `{"type":"figs","seq":[…],"opts":[…]}`），前端识别后渲染成**真表格 / 图表 / SVG 图形选项**；纯文字材料照旧。
- 用在两处：**每日巩固测试**（`_gen_dtest`）和**题库·模拟卷**（`gen_quiz.py`：判断 30 = 图形 8 + 定义 8 + 类比 7 + 逻辑 7；资料 15 = 2 篇程序化表格/图表 + 1 篇 AI 文字材料，各 5 题）。
- 抽检：图形题 200 道、资料题 2400 道，选项互异、数据自洽（三次产业之和 = GDP），**0 异常**。

### 每日巩固测试（任务清单 → 每日任务）

按当天学的内容出一份小测，**行测五个板块都覆盖**（以前只出常识题）：

- **模块配额**（`DTEST_QUOTA`）：10 题 = 言语 3 / 判断 2 / 资料 1 / 数量 1 / 常识 3；15 题 = 4/3/2/2/4。每题带 `module`，界面上有色标。
- **素材按板块喂**（`_dtest_material`）：常识/时政/理论 → 常识判断；我的成语收录 + 常考(高频成语/实词/上位词) → 言语理解（出逻辑填空/病句，考辨析不是背释义）；**我的错题 → 同考点变式题**。
- **图形推理：程序化出题**（`_gen_figure_q`）。不让 AI 画图——它画得出 SVG，但「图形规律」和它自己给的答案经常对不上。改由代码按规律生成 SVG：**旋转 / 元素数量 / 边数递增 / 线条数 / 封闭区域数** 五类，**答案是构造出来的，必然正确**，干扰项按「差一个属性」造（旋转题还会放一个镜像项——镜像靠旋转得不到）。200 道抽检：四选项互异、答案位置随机，0 异常。
- **资料分析：材料也程序化**（`_gen_ziliao`）。AI 会写「根据材料…」却根本不给材料，所以这块也收回代码：先造一份**内部自洽的统计数据**（等差设计，比重/增长率都是整数），再由代码算出答案，出**比重 / 增长率 / 年均增长量 / 倍数**四类，干扰项踩的是真实陷阱（分母用错年份、年均增长除以 4 而不是 3）。600 道抽检：三次产业之和 = GDP，0 异常。同一份材料出 2 问时只渲染一次。
- **材料会渲染成真表格 / 柱状图 / 折线图 / 饼图**（内联 SVG，无外部库）：band 刻度不压轴标、数据端 4px 圆角、悬停看精确值、附「📋 看数据表」核对数字。配色经 `validate_palette.js` 校验全 PASS（日间 `#1a6fb5 #c4661f #1e8449 #7a5cc0` / 夜间 `#3f92d6 #cf7c33 #2fa36c #8d72d1`），走 CSS 变量，**日/夜自动切换不用重渲染**。
- 数量关系仍由 AI 出，但要求「数字设计成能算出干净答案、正确项唯一」。
- 两种模式：**背题模式**（做一题显示一题答案）/ **测试模式**（服务端判分，交卷才给答案）。
- **做错的自动进错题本**：测试模式判分后收集，背题模式**选错立刻收**（带题干/选项/正确答案/解析/「我选了什么」；
  图形题与资料分析题另作标注，同题不重复收）。

### 40 天冲刺路线（备考规划页顶部）

对标网上「考公 140 分强度」那套，但**按人能扛住的节奏重排**：`ROADMAP_40`（`app.py` 里的常量）+ `plan_roadmap` 表（每人一行：起始日、天数）。开启后，规划助手每天**照着当天的定额和正确率目标排任务**（`_roadmap_prompt` 把它作为硬约束塞进提示词）。

- **节奏**：**6 天推进 + 第 7 天复盘日**（上午限时套题 → 下午全套订正归因 → 晚上错题过筛 + 半天休息）。连轴转 40 天必塌方，复盘日是能跑完全程的那颗螺丝。
- **三段**：打牢根基（1-12，建积累与错题闭环，不追速度）→ 专项拔高（13-28，按错题分布死磕薄弱模块）→ 套题强化（29-40，上午行测下午申论的考场节奏）。
- **每日定额**（行测题量）与**正确率目标**分阶段递进，比如资料分析 80% → 88% → 90%+。
- **模块优先级**：资料分析 ＞ 言语 ＞ 判断 ＞ 常识(积累型) ＞ 数量关系(战略选做 10 题)——性价比排序，写进提示词让 AI 照办。
- **积累类任务全部落到 App 已有模块**：晨读用「成语词语积累 + 常考」、时政用「每日时政」、睡前用「理论基础 / 要文库 / 习语金句」、错题进「错题本」、到期复习用「今日复习」、自测用「巩固测试」、演算用「草稿纸 / 草稿本」。
- 卡片显示 `第 N/40 天 · 阶段 · 进度条 · 今日定额 · 申论安排`，展开可看正确率目标表、每周要做到、纪律、阶段产出、40 天之后怎么走。
- 接口：`GET/POST/DELETE /api/plan/roadmap`；`GET /api/plan/today` 带 `roadmap` 状态。
- 顺手修了：`ntfGo` 以前只认一半 link，计划里的「错题本 / 成语 / 常考 / 真题批改 / 理论 / 古诗文 / 草稿本 / 巩固测试」点「去做 ›」没反应，现在全通。

**互监待办 · 邀请制组队**（`teams` / `team_members` / `team_requests` 表，互监待办按队隔离）：
- 搜对方账号（用户名 / ID）→ 发**组队申请** → 对方**接受 / 拒绝**（`/api/team/*`）。一人同时只在一个队。
- 组队成功自动把双方今天的规划同步进该队；**解散需对方同意**（任一方发解散申请，另一方 accept 才真正解散）。
- `/api/sync` 指纹纳入组队相关表，搭档打勾 / 申请到达能自动刷新。

**每日巩固测试**（`daily_quiz` 表，「每日任务」页签里的「🧪 今日巩固测试」）：按你**今天学的常识 / 时政 / 成语 / 素材** AI 出 6~8 道单选题，考点全部来自真实学过的内容；作答后即时判分、标出正确项与解析。按 用户+日期 缓存，可「换一套」重出。默认**本地判分**（答案随题下发）；可勾选 **🔒 服务端判分**（`?exam=1` 时答案不下发，交卷 `/api/dtest/grade` 由服务端判，更像考试）。**题量可选 10 / 15 题**；**每次交卷都留档**（`dtest_records`），「📋 测试记录」回看每次得分与逐题对错（`/api/dtest/records`、`/api/dtest/record/<id>`）。`/api/dtest`。

**连续 / 累计学习天数**（`study_days` 表）：完成一项备考规划任务、或互监任务被搭档确认，就把这天记为「学习日」。备考规划与互监待办头部都显示 **🔥 连续学习 N 天 · 累计 M 天**；**组队期间**两处共用同一份天数（完成规划或被确认互监都计入），**未组队**时只由备考规划完成计。`/api/plan/today` 与 `/api/team` 都带 `study`。

**备考信息编辑**：进「⚙️ 备考信息」有独立的**返回键**（回到计划页）；改过内容再点返回会弹「保存并返回 / 不保存 / 取消」；还有**撤回**按钮，一键还原到打开时的样子。

**计划记录 + 进度分析**（`plan_log` 表）：
- 每次重排前，**旧计划自动存一份快照**（`_plan_snapshot`）——再也不会像以前那样一重排就把上一版冲没了。
- 「📆 计划记录」按天回看：每天排了什么、完成了几条几分钟；今天被覆盖掉的旧版本也列出来，可**「恢复为今天」**（`/api/plan/restore`）。
- 「📊 分析进度」（`/api/plan/analyze`）：把最近 14 天的计划 + 完成情况 + **各模块被安排的频率**喂给 AI，指出坚持得好的、**被冷落或从没安排过的模块**（如上位词、古诗文这类日积累项，长期不练会拖后腿），并给出明后天的可执行建议。

## 四、安卓 APK

当前 **v2.7**（versionCode 18，已签名，安卓 5.0+）。

**安装**
1. 手机浏览器打开 **https://gk.gongkaopei2026.click/apk**（免登录）。
2. 安装（首次需允许「安装未知来源应用」）。
3. 打开后默认连 `https://gk.gongkaopei2026.click`；在家想更快可在「账户 → 切换服务器地址」改成局域网 IP。
4. **以后升级不用再下载**：新版会在应用内弹框提示，点「立即更新」自动下载并安装。

**原生能力**：禁双指缩放、拍照/选图/多选附件、原生 TTS 朗读、外链走系统浏览器、微信分享进/出、沉浸式全屏、跟随系统夜间、应用内更新、**手机通知栏推送**。

> **文件选择器的坑**：网页 `<input accept>` 里写的是扩展名（`.pdf`），不是 MIME。
> 早期实现直接把 `accept[0]` 塞进 `intent.setType()`，扩展名不是合法 MIME，
> 系统挑选器就退化成「只能选最近的图片」——上传真题/讲义/AI 附件都中招，
> 而没写 accept 的资料库反而正常。现在统一把扩展名转成 MIME：
> 全是图片 → 相册（`ACTION_GET_CONTENT`）；含 PDF/Word/PPT 或混合 → 系统文档界面
> （`ACTION_OPEN_DOCUMENT` + `EXTRA_MIME_TYPES`），可以浏览文件夹；有任何一个扩展名认不出来就不加过滤，宁可全部显示。

### 手机通知栏推送

消息中心的内容会直接弹到手机通知栏（就是下拉看到的那个系统通知列表），点通知直接打开 App 并跳到对应页面。

- `NotifyReceiver` 用 `AlarmManager.setInexactRepeating` 每 5 分钟拉一次 `/api/notifications`（省电，不用精确闹钟）；开机后自动恢复定时。**只在退到后台才轮询**：`onResume` 里 `NotifyReceiver.cancel`（前台有 SSE 秒推，省得每台设备开着 App 还一直空敲服务器）+ 拉一次补漏；`onStop` 里 `NotifyReceiver.schedule`。
- App 没在运行也会被系统唤起（清单里静态注册的 receiver）。
- 用 WebView 的登录 Cookie 请求，没登录就不打扰。
- 已弹过的用 `notify_last_id` 记住，不重复；一次最多弹 5 条，**只留最新的**（否则条数上限会把最新的挤掉，而 `lastId` 已推进，那几条就永远看不到了）。
- 点通知 → 传 `notify_link` 给 MainActivity → 等网页就绪后执行 `ntfGo(link)` 跳转。
- Android 13+ 会申请 `POST_NOTIFICATIONS` 权限。
- 「账户 → 手机通知」可开关，「发送测试通知」可验证系统有没有把通知挡掉。

**好友聊天消息也进通知栏**：给你发消息时，服务端会给收件人写一条 `kind='chat'` 的消息中心通知（`_chat_center_notify`，`link=chatroom:<对方id>`，每条消息一条、`dkey` 带消息 id 保证逐条能被轮询器推送）。
- **前台**：SSE 秒推 → `notifyChat()`。**APK 前台调 `GongkaoNative.notify(title,body,"chat:<id>")` 直接弹原生系统通知（秒到，不用等轮询）**；浏览器/桌面走 Web/系统通知。只要不是正开着那个人的聊天窗就弹，别的功能页也收得到。
- **后台/退出**：靠 `AlarmManager` 轮询兜底，间隔**从 30 分钟缩到 5 分钟**（不精确闹钟仍省电）。真·后台秒推得上 FCM，暂未做。
- **电脑端通知**：桌面壳(WebKitGTK)默认不弹网页通知，壳里处理 `permission-request`(放行) + `show-notification`(网页 `new Notification`)。**踩过的坑**：一开始用 `Gio.send_notification` 一直不弹——它要求 `application_id`(`com.gongkao.app`) 与安装的 `.desktop` 文件名(`gongkao-assistant.desktop`)一致，对不上就静默失败。改用 **libnotify**(`Notify.Notification`)后正常（不挑 .desktop 名）。另加**系统托盘小图标**(AyatanaAppIndicator3，「显示/退出」菜单)，点 ✕ **收进托盘不退出**（SSE 还连着、能继续收消息弹通知），像 QQ/微信（`DESKTOP_VER 4.7`）。浏览器/PWA 直接用 Web Notification。
- 聊天通知**不计入铃铛未读角标**（聊天入口有自己的红点，避免重复计数）；**读了该会话就清掉**它堆积的那几条（`chat_history` 里 `DELETE ... kind='chat' AND link=chatroom:<id>`）。

#### 壳要补齐的四件事（WebKit 里做不到，只能落到原生层）

桌面壳不只是个窗口。以下都是「网页里根本没有这个能力」，必须由壳补：

| 能力 | 为什么网页做不到 | 壳怎么做 |
|---|---|---|
| **中文输入法** | GTK3 要靠 im module 才弹候选框；从应用菜单启动时环境可能是空的 | 在 `import gi` **之前**设 `GTK_IM_MODULE=fcitx` / `XMODIFIERS` / `QT_IM_MODULE`（必须早于 Gtk 初始化）|
| **朗读** | 实测 **WebKitGTK 根本没有 `speechSynthesis`** —— 浏览器朗读接口不存在，按钮点了必然没反应 | 网页 → 壳消息桥（`window.webkit.messageHandlers.gk`）调**系统 TTS**，两档引擎可切（见下）。壳把探测到的引擎注入 `window.__ttsEngines`，网页据此决定给不给切换 |
| **文件选择框** | WebKit 会把网页 `accept` 里混着的 `image/*` 和 `.pdf/.docx` **过滤成只剩图片** —— 上传真题时就只能选图片 | 接管 `run-file-chooser`，自己给全套过滤器（文档+图片 / 文档 / 图片 / 所有文件）|
| **截图** | 浏览器抓不了 OS 屏幕；GNOME 自己的 `org.gnome.Shell.Screenshot` **被禁**（`AccessDenied`）| 走官方门路 **xdg-desktop-portal** 的 `Screenshot(interactive=true)`，GNOME 弹自己的区域选择（鼠标/手写笔都能拖），图片以 data URL 回调 `window.__onShot()` |
| **拖放文件** | WebKitGTK 的 `drop` 事件里 **`dataTransfer.files` 是空的**（`dragover` 有效、高亮会亮，但 drop 拿不到文件）| 在 GTK 层接管：`drag_dest_set` 收 `text/uri-list` → 读文件 → base64 交给 `window.__onDropFiles()`，网页按当前页面路由（资料库 / 真题卷 / AI 附件）|
| **`target="_blank"` 外链** | WebKit 里 `_blank` 走的是 **NEW_WINDOW_ACTION**，不是普通导航，**默认被直接吞掉**（点了完全没反应，连报错都没有）。**在 `decide-policy` 里处理 NEW_WINDOW_ACTION 也没用 —— 实测在真壳里就是走不通** | 改走**消息桥**：网页拦下外链 → `postMessage({a:'open', url})` → 壳用 `Gio.AppInfo.launch_default_for_uri` 调系统浏览器。而新闻视频**根本不再往外跳了**（改成 APP 内播放，见上） |
| **「验证通过」是假的** | 修上面那条时，我用**自己搭的简易 WebView** 测，报「端到端通过」—— 但那不是壳的真实构造，真壳里其实没调起浏览器。而且检测脚本两次误报 ✅：`grep`/`pkill` 把**我自己的 bash 命令行**也匹配上了（命令行里含待匹配的串） | 验证一律**直接 import 壳的模块、用它的 `Gongkao` 类**跑（WebKit 设置、消息桥、decide-policy 全在里面），只把窗口挪到屏幕外；进程匹配用字符类避开自己（`922[2]`）|
| **粘贴图片** | WebKit 往 `<textarea>` 里 Ctrl+V 粘图**粘不进去**（它只认文字）| `on_key` 拦 Ctrl+V：剪贴板里**有图才接手**（转 PNG → `window.__onPasteImage()`），是文字就放行；右键菜单也追加一项「粘贴图片」|

#### 桌面版朗读引擎（两档可切）

在「账户 → 🔊 朗读音色」里切：

| 引擎 | 音质 | 联网 | 怎么放的 |
|---|---|---|---|
| **Piper**（默认）| 神经语音，自然 | ❌ 不用 | 出 raw PCM 直接管道喂 `aplay`，**边合成边播**不用等整段。实测 RTF **0.098**（合成 6.4 秒语音只花 0.63 秒）|
| **微软在线** | 最自然，4 个音色可选 | ✅ 要 | `edge-tts` 出 mp3 → **GStreamer** 播（系统里没有 mpg123/mpv/ffplay，而 `gst-launch-1.0` 是 GTK 自带的）|

装引擎：`./desktop/install-tts.sh`（装到 `~/.local`，不碰系统 Python，也**不进 .deb** —— 这俩加起来 90MB）。

> ⚠️ **曾经有第三档「系统默认」= speech-dispatcher（`spd-say`），已彻底删除。** 它的 PulseAudio 输出模块会**段错误**，内核日志实锤：
> ```
> kernel: speech-dispatch[8338]: segfault at 0 ... in spd_pulse.so
> systemd: speech-dispatcher.service: Main process exited, code=dumped, status=11/SEGV
> ```
> 空指针，崩的时候正好有蓝牙音频设备在连接（切默认音频设备时踩的）。这是 Ubuntu 自带组件（speech-dispatcher 0.12.1）的 bug，不是我们能修的。
>
> **而放大伤害的是我们自己**：`_tts_stop()` 原来在 **GTK 主线程**上跑 `subprocess.run(["spd-say","-C"], timeout=2)`。speech-dispatcher 一崩，这句就一直等到超时 —— **每点一次朗读，界面就冻 2 秒**，看着就像「桌面卡死了」。
>
> 教训：**主线程上一个阻塞调用都不能有**。现在 `_tts_stop()` 只杀自己的进程组，不碰任何外部守护进程。

**读长文不「一顿一顿」的关键**：段与段之间原来是**按字数估时长**推进的（估短了打断、估长了卡壳）。现在壳**盯着播放进程，真读完那一刻**才回调 `window.__ttsEnd(id)` 让网页接着读下一句，超时只作兜底。

> 网页传来的音色字符串会被拼进 shell，所以走**白名单**（`EDGE_VOICES`），不在表里的一律退回默认。

> ⚠️ **坑（踩过）**：portal 的 `a{sv}` 选项必须传**普通 dict**（只有值是 `GLib.Variant`）。
> 先包成 `GLib.Variant("a{sv}", {...})` 再塞进 `(sa{sv})`，PyGObject 会把它当 dict 迭代 → `KeyError(0)`，**D-Bus 调用根本没发出去**。
> 而异常若被 `except: pass` 吞掉，表现就是**「点了没反应」**，完全没线索。
> 因此壳里加了 `_toast()`：**出错直接在网页上弹提示，不再静默失败**。

> ⚠️ **第三个坑**：PyGObject 里 **`GLib.filename_from_uri()` 只收 1 个参数**（`GLib.filename_from_uri(uri)[0]`）。
> 写成 `filename_from_uri(uri, None)` 会抛 `TypeError` —— 若被 `except: continue` 吃掉，
> 表现就是「拖进来的文件读不出」「截图抓到了却拿不到文件」。**同一个错误同时藏在拖放和截图两处**。

> ⚠️ **另一个坑**：悬浮球记住的位置要在**启动时和窗口变化时按当前窗口夹回可视区**（`fabClamp`），
> 否则在更小的桌面版窗口里，球会停在窗口**外面** —— 表现是「悬浮球不见了」。

#### 桌面版自动更新（两种更新，提示不一样）

桌面壳会注入 `window.__desktop` / `window.__desktopVer`，网页据此在**启动后 3.5s、每 30 分钟、切回窗口时**静默问一次 `GET /api/desktop/version`，有更新才弹窗（「以后再说」记进 `localStorage.skipUpdate`，同一版不再打扰）：

| 改了什么 | 判断依据 | 弹窗提示 | 点一下会 |
|---|---|---|---|
| **只改网页**（绝大多数改动） | 服务器 `sw` 版本 ≠ 本次启动时的版本 | 「有新内容更新 · **不需要重新下载客户端**」 | **刷新更新** → `location.reload()` |
| **改了桌面壳本身**（少数） | 服务器 `deb_code` > 本机 `__desktopVer` | 「发现桌面版新版本 vX · 需重新下载安装包」 | **下载更新** → 下载 .deb 到「下载」文件夹，下完弹窗告诉你怎么装 |

- 壳内版本号由 `build_deb.sh` 用 `sed` 注入，恒等于包版本；`version_code` = 版本号去掉点（`3.2 → 32`）。
- 壳新增 `download-started` 处理：下载的文件（更新包、导出的附件）存到系统「下载」文件夹，完成后回调网页 `window.__onDownloaded(path)`。
- 账户页「💻 桌面版」区块可手动**检查更新**、刷新页面（安卓专属的通知/切服务器按钮在桌面版自动隐藏）。

## 七、踩过的坑（改代码前先看这个）

这些都是**真出过问题**的，且大多**表现为「没反应」而不是报错**——最难查。

### 1. 静默失败是最贵的 bug

| 现象 | 真因 |
|---|---|
| 桌面版「点了截图没反应」 | portal 的 `a{sv}` 传成了 `GLib.Variant` 而不是普通 dict → `KeyError(0)`，D-Bus 调用**根本没发出去**；而异常被 `except: pass` 吞了 |
| 计划里「巩固测试」点了不跳转 | 跳的是 `tkSwitch('todo')` —— **这个页签根本不存在**（有效的是 `plan / daily / shared`），静默失败 |
| 复习取不到常考词、巩固测试也取不到言语素材 | SQL 里 board 写成「高频成语 / 实词搭配」，**库里实际叫「成语 / 实词」** → 两处同时静默失灵 |

👉 **原生壳里已加 `_toast()`**：出错直接在网页上弹提示。写新功能时**别再 `except: pass`**。

### 2. AI 不肯给的东西，就别指望它给

- 它会写「根据材料…」**却根本不给材料** → 资料分析的材料改成 `figgen.py` **程序化生成**。
- 它画得出 SVG，但**图形规律和它自己给的答案对不上** → 图形推理也改成程序化生成，**答案由构造保证**。
- 它挑「原文重点」时会**改写句子** → 时政划重点要求**逐字复制**，服务端**逐条核对**，对不上的直接丢弃（宁可少标，不能标错位置）。
- 它对「多少字」很不敏感 → 参考范文/给定资料都要**生成后校验字数、超欠自动重写**。

### 3. 平台能力要先探测，别假设

- **WebKitGTK 没有 `speechSynthesis`** → 朗读只能借系统 TTS。而系统自带的 speech-dispatcher **会段错误**（见「桌面版朗读引擎」），只好自己装 Piper —— **「借系统」不等于「系统靠谱」**。
- **原生壳的主线程上，一个阻塞调用都不能有**：`subprocess.run(..., timeout=2)` 看着人畜无害，被调的守护进程一挂，界面就是冻 2 秒。
- **WebKit 的文件选择器**会把 `accept` 里混着的 `image/*` 和 `.pdf` **过滤成只剩图片**。
- **`getCoalescedEvents()` 在部分 WebKit 上返回空表** → 不做兜底的话，一笔只剩落笔那一个点，画出来是个小点。
- **GNOME 的 `org.gnome.Shell.Screenshot` 被禁**（`AccessDenied`），只能走 xdg-desktop-portal。

### 4. 同样的功能不要写第二遍

- 申论手写板卡、草稿本却很顺 —— 因为手写板**每次移动都重画全部笔画**，没用草稿本那套「离屏层 + rAF 节流 + 合并采样」。统一后：31 笔时，一笔移动 60 次的处理耗时 **1ms**。
- 停靠面板抽成 `createDock` 后，**AI / 草稿纸 / 给定资料**三处共用一份实现，不会各自走样。

### 5. 输入法（中文）

**任何回车处理都必须先判断 `e.isComposing`**。用 fcitx 打中文时回车是「确认候选词」，
若被当成「提交」，组字会被打断 —— 表现是**「只打得出英文字母、候选框弹不出来」**。
代码里有 `composing(e)` 助手，新写的回车处理**必须用它**。

### 6. 拆模块拆出来的首屏慢：56 个同步脚本 = 56 个阻塞请求

前端从 15 个文件拆成 56 个后，`index.html` 排了 56 个同步 `<script>`，每个还 `no-store`（每次全量重下）、无 gzip。手机走代理/隧道时首屏迟迟出不来，6 秒兜底把启动页一撤 → **首页空白、悬浮球点不动**（悬浮球和 `init()` 都在第 39 个脚本 `sync.js` 里，没加载到就是死的）。后端接口实测全部 <8ms，慢**根本不在后端**。

👉 修法（`app.py` + `assets.py`）：**源码保持 56 个模块不变**，服务端合成一个 bundle；文本响应 gzip；bundle 带版本号走 `immutable` 长缓存，css/js/sw 走 `no-cache`（带 ETag 回源校验，不发旧的），只有外壳页才 `no-store`。首屏 **57→3 个请求、836KB→约 240KB**。

同源的两条经验：**打勾这类操作别整表重渲**——规划/每日/互监三处改成「点击即翻勾、后台发请求、失败再回滚」的乐观更新（互监只重画点的那一行），去掉了原先的「跳加载 + 回到顶部」。**角标别拉整份数据**——首页复习角标只要一个数字，`/api/review/today?count=1` 把 80KB 砍到 254B。
